# VISUALS -- seeing levels the way Geometry Dash draws them

Owner: the "visuals" session (2026-11-23). Goal: no session decorates blind. The viewer draws a level with
GD's own sprites from the user's install, and a catalogue shows what every object id looks like.

## Rule: RobTop's art never leaves the user's PC

The sprite sheets, backgrounds and icons are read at run time from the game's `Resources` folder by
`tools/serve.js` (`GET /gdres/<file>`, `/gdres/icons/<file>`; `GD_GAME` overrides the Steam path). Nothing
of the art is copied into the repo, onto the phone page or into an Artifact. Rendered pictures of it
(`local/shots/`, `local/catalogue/`) live in the never-committed `local/`. Committed are only facts:
object id -> frame names, offsets, colour roles, layers.

## What is built

- **Viewer "GD art" button** (on by default when served by `tools/serve.js`, with "game look" on):
  objects as GD's sprites, tinted by the level's colour channels at that moment (header + colour
  triggers, `lib/look.js`), in GD's z-layers and z-order, with glow; background (`game_bg_NN`, header
  `kA6`), middleground (`fg_NN` + `fg_NN_2`, `kA25`), ground (`groundSquare_NN` + `_2`, `kA7`), floor line
  (`floorLine_0N`, `kA17`), the player icon of each mode (icon 1, the user's lime/cyan). Ids with no
  known frame fall back to the shape drawing; "GD art" off = the shapes of `lib/look.js` as before.
  Off on `file://` and on the phone page (`tools/web.js` strips it; see "Phone").
- `lib/art.js` -- plist parser (TexturePacker format 3), object -> sprite tree, tinting (multiply on a
  cached canvas per frame and colour), drawing, scenery, icons. Tree part runs in node.
- `lib/objects_art.js` (generated by `tools/import_art.js`) -- OpenGD's object table, GD 2.1, 1541 ids
  up to 1910: root frame, child sprites (frame, offset, rotation, scale, flip, z, anchor), colour role
  per sprite (base = main channel, detail = detail channel, black = 1010), default z-layer, z-order,
  main/detail channels; plus the 12 glow frames of `GameObject::getGlowFrame`.
- `lib/objects_frames.js` (generated by `tools/import_frames.js`) -- GD 2.2's OWN id -> root frame
  table, 4093 ids (1..4539), read out of the user's `GeometryDash.exe` (ObjectToolbox's init is a long
  run of `mov [rbp+x], id ; lea rdx, "frame.png" ; call`). Agrees with OpenGD on 1434 of 1541 ids; the
  rest are objects whose root sprite GD swaps in setup (OpenGD has the swapped one), so OpenGD wins
  where it has the id. For 2.2-only ids we know the root frame only: no children, layer T1, channel 1004.
- `tests/art_tables.js` -- plist parsing, trees, and every named frame exists in the install's sheets.

## Facts (checked against the user's recordings)

How: viewer "compare" panel, level start offset set by eye, "save comparison" -> `local/shots/`.
Driven from the browser console: load a level (`load(name, levelStr, solution)` -- officials from
`../local/official_NN.json`), set `cmpRec`, `cmpT0`, `t`, then `cmpShot()`.

- Cycles (official 9) vs `GD claude-rec 2026-11-22_19-09-46.mkv` (attempt 2 starts at 0.9 s), level t=3.2:
  blocks, spikes, chains, ground spikes, orb, portal and ground match (shot
  `local/shots/cmp 2026-11-23T01-24-52-969Z.png`).
- GDLM 41 vs `18-48-19.mkv` (attempt 1 at 7.62 s), level t=5.4: background blob size, hills,
  grid blocks, ground match.
- **Channels 1005/1006 are the player's own colours** whatever the header stores (GDLM 41's header
  says orange for 1005; its P1 deco is lime in the game). They **blend (additive) by default**: Cycles'
  old header has no flag and its ground spikes and chains show lime added over purple (yellowish).
- **Ground spikes 18-21, chains, antennas' balls default to 1005** (OpenGD), confirmed by the colours above.
- **Background**: the 2048 px tile is drawn at natural size (512 units), bottom on the ground line.
- **Middleground**: only the top ~40 units of the `fg` pictures show above the ground; the rest is under it.
- **Glow** takes the object's main colour (OpenGD; Cycles' white blocks glow white).
- **Rotated frames**: the plist `textureRect` size is the upright size; the sheet holds it turned 90
  degrees clockwise (w and h swapped). Getting this wrong squashed `rod_02`.
- **Portals**: front and back halves are separate frames (`portal_NN_front`, `_back`), each with its own
  trim offset; both centred on the object give the full oval seen in the game.
- Old-format headers (official levels in `local/`): `kS29` bg, `kS30` ground, `kS31` line, `kS32` obj,
  `kS33..36` colours 1-4, `kS37` 3DL; `kS38` field 4 is read as "player colour 1/2" (not verified).

## Open (not done or not sure)

- GDLM 41's white blocks show **lime edges** in the game, our render white. The installed copy has more
  deco than `levels/gdlm_41_classic.gdlvl`, so it may carry other colours; re-check with a level whose
  installed copy is known (install, record, compare).
- The rod (antenna) ball draws as a ring; the game shows a filled pale ball. Ball offsets are by eye.
- Order of the player vs T1 objects (we draw the player after everything, OpenGD puts it under T1).
- The camera's vertical follow and the bg's slower vertical parallax are not the game's.
- 2.2-only ids (1911+): root frame only, no child sprites, default layer/channel guessed (T1, 1004).
  2.2 objects made of several sprites (most of the 2.2 deco families, animated objects) will look partial.
- Not drawn: particles (portals, orbs, pads), animated objects (fire, saws turning, pulsing), HSV (keys
  41-44), copy-colour channels (kS38 field 9), pulse triggers, LBG exact shade, colour trigger keys 15/16
  (player colours), "extra" sprites of portals/orbs (arrows), the ground's second layer for every set,
  middleground for 1.x levels.
- Animated texture objects (ids 14, 37, 300-445 area...) have no frame in either table.

## Phone

The phone page must not carry RobTop's art. Options (not built): (a) the user picks the sheets from the
phone's own GD install once ("add art", like "add song"), kept in that browser's IndexedDB; (b) the PC
renders per-level preview frames into `local/` and the phone page fetches them only from the user's own
machine (needs the PC on). Until then the phone page stays shape-drawn (PHONE.md).

## How to update

- After a GD update: `node tools/import_frames.js` (re-reads the exe), `node tests/art_tables.js`.
- OpenGD table: see the top of `tools/import_art.js` (clone OpenGD to a scratch folder, run it on it).
- Not used, on purpose: GDRWeb (MIT, but its README forbids use for AI level generation or modification,
  which is what this project does) and GDWeb (CC BY-NC-ND).
